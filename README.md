# krkr2web

面向固定 Android WebView 89 的通用 KRKR2 Web 模拟器。用户从服务端配置的游戏库
下载完整资源到浏览器站点存储；页面保持在 WebView 内时，断网后仍可启动、游玩和
读取本地存档。首个完整
验收游戏为《千恋万花》。

## 项目状态

项目已完成第一轮实机可行性验证以及 D0-D4 阶段门禁，当前进入 D5《千恋万花》兼容
与性能开发。D4 已根据目标腾讯 TBS 宿主的实测限制改为同页播放器。D3 已在
目标 WebView 89 通过原生绘制、交互、KAGParser 与真实 `.ks`
剧情闭环、声音、触摸、存读档和 30 分钟稳定性；键盘和标准手柄增强输入已通过
Windows 桌面自动门禁。

已在目标设备确认：

- Android 13、Chromium WebView 89、8 核、4 GB 内存、Mali-G52 MC2。
- 站点配额约 27.19 GiB；5 GB IndexedDB 数据在关闭 App 和整机重启后均保留。
- IndexedDB 4 MiB 分块读写、WebGL 2、Web Audio、H.264、触摸和手柄 API 可用。
- 服务器 COOP/COEP 正确，但目标 WebView 不提供 `SharedArrayBuffer`、跨源隔离或
  Wasm 共享内存；多 Worker 共享内存方案已排除。
- Cache Storage 可用；Service Worker 在目标腾讯 TBS WebView 中注册失败。产品不再
  依赖它，断网能力通过同一文档内切换实现。
- D0 最小 Wasm 已在目标 Chrome 89 WebView 完成 10/10 项实机检查，报告编号为
  `20260813-042500-ed8c1130`。

当前技术路线是**单线程 KRKR2 Wasm + Asyncify + IndexedDB 分块读取**。第一开发
门禁要求在实机上完成大于 2 GiB 偏移、跨块、10,000 次随机读取、页面响应和内存
验证。详见 [开发路线图](docs/10-development-roadmap.md)。

D1 快速探针已在目标 WebView 89 通过，包含 5 GiB 逻辑文件、4 MiB 实际分块、
Asyncify 同步式读取接口和 10,000 次随机读取。实机报告编号为
`20260813-050844-4e39fcd2`。后续报告 `20260813-060205-c2cb3221` 证明后台 51.36 秒
后可恢复读取，并连续运行约 13 分 57 秒；期间缓存、Wasm 堆和 JS 堆均无增长趋势。
D1 已通过，产品阶段仍保留真实引擎 30 分钟和《千恋万花》60 分钟稳定性验收。

D2 已为《千恋万花》三个 XP3 生成内容版本 Manifest：总计 `4,044,268,983` 字节、
`966` 块。客户端采用两个并发 Range 请求、逐块 SHA-256 后独立提交、可恢复下载、
坏块单独修复和分批删除；只有全量复核成功后才允许启动。操作与门禁见
[D2 游戏下载与缓存验证](probes/d2-downloader/README.md)。

D2 已在目标 WebView 89 完成 4.04 GB、966 块实机验证：两次暂停/恢复、全量
SHA-256 复核和原子完成状态均通过；模拟坏块只重下一个 4 MiB 块；删除按 31 批
完成，站点用量从 4.46 GiB 降至 707.22 MiB。三份报告编号为
`20260813-074849-46fc47d1`、`20260813-075135-c89770b9` 和
`20260813-075147-744e8412`。D2 已通过。

D3 当前引擎基线为单线程 KRKR2/SDL2 Wasm + Asyncify。约 8.47 MB 的自制 XP3 已覆盖
图片与开源字体读取、KRKR2 文字绘制、输入、PCM WAV、IDBFS 存读档，以及真实
KAGParser 对 `.ks` 的跳转、宏、条件、选择和分支状态恢复。Wasm 内存保持 64 MiB，
XP3 缓存峰值约 8.47 MB。构建扫描确认不含 pthreads、共享内存、SIMD、JSPI 或 Wasm
原生异常。实机与后续操作见 [D3 KRKR2 引擎验证](probes/d3-engine/README.md)。

D3 第一轮已在目标 Android Chrome 89 WebView 实机通过：报告
`20260813-091827-db864272` 记录了 `scriptFrameReady=true`、9 次无错误 IndexedDB
读取、64 MiB Wasm 内存以及 `1920 x 1128` 实际 Canvas；测试者人工确认画面与预期
一致。

D3 第二轮也已在目标 WebView 89 通过。报告 `20260813-101410-46beabc7` 确认图片、
文字、触摸与兼容点击、PCM WAV 播放和本机写档成功；报告
`20260813-101444-870b6159` 确认页面重开后从 IDBFS 恢复到进度 2。两次测试均无
XP3 读取错误，Wasm 内存为 64 MiB，XP3 缓存峰值约 8.46 MiB；测试者确认画面和
声音均正常。

D3 第三轮桌面门禁已通过。构建从锁定的 `krkr2` 提交导入 KAGParser，并修复其状态
恢复遗漏行列位置的问题。自有 `scenario.ks` 已实际执行跳转、宏、条件、左右选择和
分支；KAG 状态保存在第 24 行第 24 列，页面重开后从同一位置继续。最终报告完整保留
`intro`、`condition`、`branch`、`restored` 四阶段，桌面报告编号为
`20260813-105513-aa14732c`。

D3 第三轮目标 WebView 89 实机复核已通过核心门禁：测试者确认 `.ks` 推进、左右选择、
分支画面和声音正常；彻底退出 WebView 后重新进入，报告
`20260813-111835-131c5012` 从 `left` 路线第 24 行第 24 列恢复，64 MiB Wasm 和 XP3
读取均无错误。原测试页的 `location.reload()` 被腾讯 X5/TBS 宿主忽略，因此页面内
“重开验存档”无反应；这属于测试页导航兼容问题，不是写档或读档失败。现已改为先
确认 IDBFS 同步，再通过带唯一参数的原生站内链接重开并自动启动。修复后的实机报告
`20260813-112649-464d64aa` 记录 `restartRequested=true`、`saveSynced=true`，并再次从
`left` 路线第 24 行第 24 列自动恢复，按钮兼容问题已关闭。

D3 增强输入门禁已在本机 Windows Chrome 通过。键盘的 Enter/Esc/左右方向，以及
标准 Gamepad API 手柄的 A/B/十字左右，均经 SDL 原生 Emscripten 输入链送达 KRKR/TJS；
按下与松开成对，覆盖推进、确认、取消和选择移动，并完成右路线写档。键盘报告编号为
`20260813-114218-09ff29d6`，手柄报告编号为 `20260813-114222-478688a7`。目标设备无法
连接外接键盘或手柄，因此该项按设备能力仅做桌面验收；触摸仍以目标实机结果为准。
稳定性探针使用 KRKR/TJS 每秒心跳证明引擎仍在执行，只累计页面可见、心跳正常且
事件循环未长时间停顿的时段。目标 WebView 89 最终报告
`20260813-133216-9e5c1081` 保留一次连续 `1,800,250 ms`、累计 30 分钟和 32 个采样；
XP3 缓存峰值 `8,880,108` 字节，Wasm 内存 64 MiB，JS 堆增长为 0，无存储或运行时
错误，全部稳定性门禁为 `true`。此前报告 `20260813-132241-07f8ed83` 暴露了旧 WebView
中全局存储桥接属性生命周期问题；修复为作用域内稳定引用并加入自动回归后，原有
30 分钟证据无损迁移。D3 整体通过，主开发任务切换到 D4。

D4 第一轮已经提供可直接操作的横屏产品壳：游戏库、游戏详情、下载管理、设置、完整
下载、暂停/继续、校验、删除和本地启动。产品播放器按 `gameId` 隔离 IDBFS 存档，每
30 秒及页面进入后台/退出时同步。实机报告 `20260813-144755-3a440cb7` 确认腾讯
TBS 046295 无法注册 Service Worker，且该宿主断网后只要 URL 变化就会显示网络错误页。
因此产品已改为联网打开游戏库时预载约 7 MiB 引擎，并在同一 HTML 文档内切换游戏库
和 Canvas；XP3 始终只从 IndexedDB 读取。桌面自动门禁在完全禁用 Service Worker 后
通过：断网点击“启动游戏”时 URL 不变、网络请求为 0，画面正常，本地 XP3 读取无错误。
`1280 x 720`、`1280 x 800` 横屏也无溢出或控件重叠。目标 WebView 实机报告
`20260813-151518-903d7485` 进一步确认：点击启动时设备已断网、引擎已提前准备、启动
网络请求为 0，原始长 URL 完全不变；游戏进入 `ready`，XP3 读取 668 次且无错误，
Wasm 内存为 64 MiB，存档同步 3 次。测试者确认画面、声音和操作正常。D4 整体通过，
退出 WebView 后的断网冷启动不属于产品范围。

D5《千恋万花》兼容与性能开发已进入实质阶段：三个真实 XP3（约 4.04 GB）已能通过
D5 兼容探针在本机无头 Chrome 启动，引擎完成索引读取、文件树重建（39,946 个文件）、
真实 `startup.tjs`/`boot.tjs` 与全部系统脚本加载、字体加载，累计 848 MiB 读取无错误。
当前首个硬阻断是写压缩存档时 zlib deflate 的 Asyncify 误改写触发 Wasm
“null function”崩溃；插件缺口清单、精确崩溃栈与修复优先级见
[D5 兼容与性能现状](docs/15-d5-compat-status.md)。
