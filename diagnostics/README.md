# WebView 实机检测工具

该工具只提供检测页面，不会暴露仓库中的《千恋万花》资源。服务器固定绑定
`0.0.0.0`，响应包含 SharedArrayBuffer 所需的 COOP/COEP 安全头。

## 1. 确定测试域名

使用第三方 App 实际会打开且允许 DNS 劫持的完整域名，例如：

```text
game.example.com
```

证书必须包含这个准确域名。不能先为任意域名生成证书，再劫持成另一个域名。

## 2. 生成证书并启动

在 PowerShell 中运行：

```powershell
.\tools\start_diagnostics.ps1 -HostName game.example.com -Port 8443
```

若第三方 App 只能访问标准 HTTPS 端口，以管理员身份使用：

```powershell
.\tools\start_diagnostics.ps1 -HostName game.example.com -Port 443
```

脚本会：

1. 在 `certs/` 创建开发根 CA 和域名证书。
2. 绑定 `0.0.0.0` 启动 HTTPS 服务。
3. 显示要安装的 CA 文件和 WebView 访问地址。

首次生成后，根证书位于：

```text
certs/krkr2-dev-ca.crt
```

把该根证书安装到 Android 设备的受信任凭据中。服务器私钥
`certs/krkr2-dev-ca-key.pem` 不能发给其他人，也不能提交到 Git。

Android 7 以后，第三方 App 可以选择不信任用户安装的 CA。如果 App 仍报告证书
错误，这不是 DNS 设置问题，需要改用系统信任的真实域名证书。

主页面能够打开不等于证书已被系统信任。部分 App 会在 WebView 中忽略主页面的
证书错误，但 Service Worker 使用独立的网络请求，仍会拒绝该证书。检测页会先
独立验证 Cache Storage；如果只有 Service Worker 报 SSL/证书错误，将显示黄色
“测试证书无法判定”，而不是误判为设备不支持。完整离线应用壳仍必须使用受系统
信任的证书验证。

## 3. DNS 与热点

- 让 Android 设备连接开发电脑的热点。
- 把测试域名解析到开发电脑的热点局域网 IP。
- Windows 防火墙需要允许所选 TCP 端口的入站连接。
- 在 WebView 中打开脚本显示的 HTTPS 地址。

服务器支持页面 404 自动跳转。第三方 App 即使打开
`https://测试域名/xxx/xx.html`，服务器也会返回 `302`，让 WebView 自动跳转到
`https://测试域名/` 的检测页面。不存在的 JavaScript、CSS 和 Wasm 等静态资源仍
返回标准 404，防止资源错误被隐藏。

## 4. 执行检测

1. 点击“开始检测”。
2. 检测结束后点击“上传报告”。页面显示报告编号即表示服务器已收到；报告保存在
   项目根目录的 `diagnostic-reports/`。也可使用“复制报告”作为后备方式。
3. 运行 64 MB 压力测试。
4. 若 64 MB 通过，运行 1 GB；完成后关闭第三方 App，再打开同一地址。
5. 页面显示“重启保留通过”后复制报告。
6. 最后运行 5 GB，重启设备后再次打开并复制报告。

1 GB 和 5 GB 测试会保留数据供重启校验。复制完报告后，再启动任意压力测试，
页面会先删除旧测试数据。取消或失败时页面也会尝试清理。

## 安全说明

- 该服务器只用于受控局域网开发测试。
- 只有用户点击“上传报告”时，当前页面显示的检测 JSON 才会发送到服务器。
- 报告只记录当前页面的域名和路径，不记录 URL 查询参数或 `#` 后的宿主 App 参数。
- 上传接口无账号鉴权，不要把该检测服务器直接暴露到公网。
- 不要把开发 CA 用于正式环境。
- 不要将 CA 私钥或服务端私钥交给不受信任的人。
- 正式服务必须使用公开受信任证书。
