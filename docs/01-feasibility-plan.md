# 可行性验证计划

验证采用“门禁”方式：前一阶段失败时，先解决该问题，不投入后续完整功能开发。

## FV-0：实机能力检测

使用 `diagnostics/` 页面收集以下结果：

- UA、Android 版本、WebView 版本、逻辑内存和 CPU 核数。
- HTTPS、安全上下文、证书是否被 WebView 接受。
- Service Worker、Cache Storage 和同页断网能力。
- IndexedDB 小块写入、随机读取、删除、速度、站点配额和持久化授权。
- `SharedArrayBuffer`、跨源隔离、`Atomics.wait`、共享 Wasm 内存。
- WebGL 1/2、纹理上限、音视频格式和输入设备能力。

当前结果（2026-08-12）：部分通过。IndexedDB、WebGL 2、音频、视频格式和输入能力
通过；共享内存失败；Cache Storage 通过但 Service Worker 注册失败。已取得服务端
报告 `20260812-145616-0060df64`。

## FV-1：站点存储压力测试

检测页提供手动启动的 64 MB、512 MB、1 GB 和 5 GB 测试。正式测试按以下顺序执行：

1. 写入 64 MB，校验首、中、尾块并删除。
2. 写入 1 GB，关闭第三方 App，重新打开并校验，然后删除。
3. 写入 5 GB，重启设备后校验，再删除。

测试使用 4 MiB 分块和逐块事务，不一次性分配大内存。

通过条件：5 GB 写入成功；关闭 App 和重启设备后仍存在；随机读取正确；写入期间
没有崩溃；删除后空间可回收。若只有 4 GB 左右配额，不足以容纳游戏、存档、应用
壳和升级临时空间，判定不通过。

当前结果（2026-08-12）：**通过容量与持久化门槛。** 目标站点配额约 27.19 GiB，
5 GB 数据写入成功；测试者确认关闭第三方 App 后重新打开仍可读取，整台设备重启后
重新打开也仍可读取。自动报告中的该次压力测试状态为“用户取消”，因此上述 5 GB
完成与重启保留结论作为人工确认记录。删除后的空间回收仍应在下载 PoC 中回归。

## FV-2：文件读取桥 PoC

目标 WebView 已确认没有 `SharedArrayBuffer` 和 Wasm 共享内存，下面的原主方案不再
作为可交付路线，仅保留为现代浏览器对照实验：

实现最小的 Engine Worker 与 I/O Worker：

- Engine Worker 发起指定文件、64 位偏移和长度的同步读取。
- I/O Worker 异步读取 IndexedDB 分块，将结果写入共享 Wasm 内存。
- Engine Worker 使用 `Atomics.wait/notify` 等待结果。
- 连续执行顺序、随机、跨块和并发读取。

通过条件：能够读取超过 2 GiB 的偏移；10,000 次随机读取无错；等待时页面触摸和
动画不冻结；内存保持在预算内。

目标实机 PoC 改为验证不依赖共享内存的方案：

1. 优先验证单线程 KRKR2 Wasm + Asyncify，将同步 C++ 文件读取挂起并等待
   IndexedDB Promise 完成。
2. 验证 64 位偏移、跨 4 MiB 分块读取、10,000 次随机读取和异常恢复。
3. 若 Asyncify 的兼容性或性能不达标，评估不依赖 Service Worker 的同页后备方案；
   目标 TBS 宿主已确认不能使用 Service Worker。

通过条件保持不变：能够读取超过 2 GiB 的偏移；10,000 次随机读取无错；页面触摸
和动画不冻结；典型读取性能可支撑剧情 20 FPS；内存保持在预算内。

## FV-3：下载与恢复 PoC

- 服务端提供 Manifest、HTTP Range、稳定版本号和每块 SHA-256。
- 下载过程中强制断网、关闭 App 和杀进程。
- 恢复后只补齐缺失或损坏的分块。
- 完成标记必须最后写入；未完成资源不能启动游戏。

通过条件：4 GB 资源可以多次中断恢复；损坏一个本地块后只重下该块；下载期间
峰值内存不随已下载大小增长。

## FV-4：Chrome 89 引擎基线

以 `fenghengzhi/kirikiroid2-web` 为主要基线，回退其现代浏览器依赖：

- 移除 JSPI，改用单线程 Wasm + Asyncify 文件读取桥。
- 不使用 Wasm 原生异常和 reference types。
- 固定 Emscripten 工具链，并声明 Chrome 89 最低目标。
- 维持 64 位文件大小和偏移。
- 先在小型无特殊插件的 KRKR2 游戏上启动。

通过条件：Chrome 89 实机可以稳定进入基础测试游戏，完成图像、文本、音频、输入
和存档闭环。

## FV-5：《千恋万花》兼容验证

依次验证 XP3 索引、脚本启动、motionplayer、PSB/PIMG、图形层、语音/BGM、存档和
长时间剧情。每发现一个缺失插件或脚本行为差异，记录到游戏兼容清单，不做无法
追踪的临时修改。

通过条件：达到 [产品范围](00-product-scope.md) 中的首版验收标准。

## FV-6：视频技术验证

首版主流程稳定后单独验证视频。优先验证服务端预转码、浏览器硬件解码和同页媒体
适配层；Wasm FFmpeg 只作为无法转码资源的后备方案。

通过条件：片头和剧情视频音画同步、可跳过、播放结束能正确回到脚本，离线状态
可播放，内存和帧率不会导致 App 被系统杀死。
