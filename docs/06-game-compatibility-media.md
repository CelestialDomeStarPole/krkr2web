# 游戏兼容与视频路线

## 兼容等级

| 等级 | 页面含义 |
| --- | --- |
| 已验证 | 在目标 WebView 和指定资源版本上通过完整验收 |
| 可能可用 | 引擎和插件扫描未发现明确阻断，但尚未完成实机流程 |
| 不兼容 | 已知缺失插件、脚本能力或媒体格式会阻止游玩 |

每个游戏绑定明确资源版本和 `engineProfile`。兼容补丁只能作用于对应游戏或明确的
插件族，避免修复一个游戏时破坏其他游戏。

## 插件策略

KRKR2 游戏中的 `.dll` 是 Windows 原生插件，浏览器不能直接加载。模拟器必须在
Wasm 引擎中实现同名插件接口。常见插件逐步内置；未知插件由扫描工具列出并标记
风险。

《千恋万花》资源包含 motionplayer、psbfile、layerExDraw、PackinOne、TextRender、
音频插件及多个游戏/平台专用 DLL。参考分支已经实现其中一部分，并含有针对
《千恋万花》的 motionplayer 修复，因此作为主要代码基线。

## 视频是必做能力

首版允许跳过视频只是排期安排，不代表视频被移出范围。《千恋万花》的
`video.xp3` 包含 28 个 WMV；Chrome 89 不能直接播放 WMV。

### 首选路线：服务端媒体预处理

1. 发布游戏时扫描 XP3 中的视频。
2. 在服务端离线提取并转为目标 WebView 可硬件解码的 MP4/H.264/AAC；具体编码
   能力以检测报告为准。
3. Manifest 记录原始游戏路径到转码媒体 URL 的映射。
4. 游戏请求 WMV 时，视频适配层改为读取转码副本。
5. 转码视频同样按块下载到 IndexedDB。同页媒体适配层为 `<video>` 提供 Blob/Media
   Source 输入，实现当前页面断网后的播放、拖动和有界缓冲；不得触发页面导航。

这条路线能利用设备硬件解码，最适合 G88 和 4 GB 内存。

### 后备路线：Wasm FFmpeg

对于不能预处理的资源，在 Wasm 中使用裁剪后的 FFmpeg 解码。该路线 CPU、内存和
包体成本更高，必须限制解码线程、帧缓存和分辨率，不能作为首选。

## 视频验收

- 画面尺寸、层级和宽高比正确。
- 音画同步，音量受游戏设置控制。
- 暂停、继续、跳过和播放结束事件与脚本一致。
- 当前页面保持打开时，断网后正常播放。
- 播放过程不造成持续内存增长或 Android 杀进程。
