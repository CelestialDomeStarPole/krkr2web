# 开发就绪评审

## 结论

项目文档和实机证据已经足够支撑持续开发。D0-D4 已通过目标 WebView 89 实机门禁，
当前可以进入 D5《千恋万花》兼容与性能开发。

这意味着 4 GB 级存储、分块读取和最小 KRKR2 可玩闭环均已有实机证据；目标宿主不支持
断网页面导航，因此只验收用户要求的“保持当前 WebView 页面后断网继续使用”。

## 已冻结的事实

- 目标是不可升级的 Android Chromium WebView 89，固定横屏，设备内存 4 GB。
- 游戏只能由管理员在服务端配置；用户不能选择本地文件或输入资源地址。
- 游戏资源先完整下载到 IndexedDB，断网后从本地启动；存档只保存在本机。
- 目标设备已完成 5 GB IndexedDB 写入，并通过关闭 App 和设备重启后的保留验证。
- 游戏文件按 4 MiB 分块保存；4 GB 资源不能整体进入 JS 或 Wasm 内存。
- 目标 WebView 不提供 `SharedArrayBuffer` 或 Wasm 共享内存，产品构建禁用 pthreads。
- 当前文件桥为单线程 Wasm + Asyncify + IndexedDB 异步分块读取。
- Service Worker 在目标腾讯 TBS 宿主中注册失败，不是产品依赖或后续门禁。
- 断网后 URL 变化必定触发宿主错误页；产品必须在同一 HTML 文档内启动和返回游戏。
- 视频是正式产品必做能力；首版可延期，但不能从产品范围删除。
- 产品是通用 KRKR2 模拟器，《千恋万花》只是首个完整验收游戏。

## 尚未冻结的事项

以下事项必须由对应开发阶段的实测结果决定，不能在实现前写死：

- 最终 Emscripten、CMake、vcpkg 和依赖版本。
- Asyncify 对真实 KRKR2 文件调用链的代码体积、性能和栈空间成本。
- Wasm 内存上限、图像缓存上限和 IndexedDB 热块缓存大小。
- 下载并发数，以及是否需要根据设备负载自动降级。
- 同页引擎预载对《千恋万花》运行时内存峰值的影响。
- 触摸手势和可视控制层的最终交互方案。
- 各游戏专用插件的支持顺序，以及视频预转码的发布流程。

## Go / No-Go 门禁

| 门禁 | 可以继续的条件 | 停止条件 |
| --- | --- | --- |
| D0 构建基线 | 最小 Wasm 在目标 WebView 89 加载；禁用特性检查有效；构建可复现 | 无法生成 Chrome 89 可解析的构建，或依赖只能使用已明确不支持的 Wasm 特性 |
| D1 文件读取 | 超过 2 GiB 偏移、跨块和 10,000 次随机读取正确；页面可响应；内存有界；性能可支撑 20 FPS 目标 | Asyncify 无法覆盖真实调用链、频繁崩溃、持续冻结页面，或内存明显超出设备承受范围 |
| D2 下载存储 | 4 GB 级下载可中断恢复；坏块可单独修复；删除后空间回收 | 必须整文件驻留内存、恢复会重下全部资源，或 IndexedDB 在真实下载压力下不可靠 |
| D3 引擎闭环 | 测试游戏完成启动、图像、文本、音频、输入和存档闭环 | 引擎核心依赖目标浏览器无法提供且无可接受替代方案 |
| D4 断网同页启动 | 页面联网时引擎准备完成；断网后 URL 不变、无网络请求并能启动已安装游戏 | 同页预载后仍必须导航或请求网络才能启动 |
| D5 首个游戏 | 《千恋万花》达到首版功能、性能和 60 分钟稳定性标准 | 关键专用插件无法实现或设备资源预算不可接受 |
| D6 视频 | 离线视频音画同步、脚本事件正确、内存稳定 | 硬件解码路线不可用且软件解码无法满足设备预算 |
